# Changelog

All notable changes to **Markdown ER Diagram** are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

> **Note:** This project is in early development (v0.x). The `.ermd` file schema may receive breaking changes before the stable 1.0 release.

## [0.1.3] - 2026-11-07

### Added

- **SQL import** — paste or open DDL and `INSERT` statements, including `mysqldump` and `pg_dump` output, in any of the
  five dialects. Tables, relations, indexes, constraints, comments and seed data come in after a preview, which also
  warns about what the diagram can't hold. Undo with `Ctrl+Z`.
- **Test tables and test data** — mark a table as test-only and give production tables test rows. They are kept in
  `<file>.ermd.test.yaml`, stay out of production DDL, schema diffs and versions, and get their own **Test DDL** with
  separate output files (`markdown-er.ddl.testOutputFile`, `testDataOutputFile`). Test tables can be hidden on the canvas.
  Without test data no file is created and the `.ermd` file doesn't change.
- **Restore a version** — put the production schema back to a saved version, as one undoable edit. Test tables and test
  data stay.
- **Compare versions** — any two saved versions, or a version and the current state, item by item: tables, columns,
  indexes, constraints and relations, with each value before and after.
- **Save status** in the toolbar (Saving… / Saved / Save failed) and **`Ctrl+S`** to save right away. Changes are still
  saved automatically.
- **DDL validation** — the DDL is not generated, and the dialog lists what to fix, when a physical name is missing or
  duplicated, a column has no type, or a relation with an FK constraint has no column. Saving the diagram is never blocked.
- **Third-party notices** in the extension package (`THIRD_PARTY_NOTICES.md`).

### Changed

- New columns start with no name and no type, instead of `Column` / `column` and the first dictionary entry. Choosing a
  dictionary type sets the logical name if it is empty.
- **Index and constraint names are optional.** Left empty, they come from the table and columns (`ix_orders_user_id`,
  `ux_…`, `uq_…`, `ck_orders_1`). The name box shows the name it will get.
- A diagram that hits a validation rule now shows errors instead of DDL. That includes columns without a type, which
  used to fall back to `VARCHAR(255)`.

### Fixed

- A UNIQUE or CHECK constraint without a name was left out of the DDL with no warning.
- Labels in panels were hard to read on a dark theme and looked disabled.
- **Export DDL** in the toolbar always opens the full DDL, even if the dialog was last left on another mode.
- `dagre` is now a runtime dependency, so the CI audit of shipped code covers it and `lodash`.

## [0.1.2] - 2026-11-03

### Added

- **Size column** in the column list — every column's length at a glance (`255`, or `10,2` for DECIMAL). Editable for
  basic types that take a size (VARCHAR / CHAR / DECIMAL); a dictionary type's size is shown read-only; other types
  take no size.
- **Auto-increment checkbox** right of PK — shows whether the column auto-increments (by default a single integer
  primary key that is not a foreign key) and lets you turn it on or off per column. Only a choice that differs from the
  default is saved.
- **Column details** — the button at the end of a column row opens the column's **comment** (output to DDL comments
  and generated docs), **default value** (SQL expression) and **design note** (never output). Comment and default
  value could not be edited in the table editor before.
- **Seed data: generated keys** — leave the auto-increment key empty and the database generates it; the column is
  marked *auto* in the seed editor. Rows with explicit ids are inserted first with the database's identity handling,
  rows without follow.
- **DDL replacements** — find / replace rules in the DDL dialog for output the generator doesn't cover (e.g.
  `GENERATED BY DEFAULT` → `GENERATED ALWAYS` on PostgreSQL). Per database or all, literal or regular expression,
  applied in order to the DDL and the data file; saved in the diagram (`ermd-ddl-replacements`).

### Changed

- The type picker chooses only the type; the size is entered in the column list (the cursor moves there).
- Integer types no longer offer a size (MySQL display widths such as `INT(11)` are deprecated); an existing one can
  still be cleared.
- The column row's *Note* button became **Details** (memo icon, filled when anything is set).

### Fixed

- Seed rows with an empty auto-increment key were inserted as `NULL`, which fails on PostgreSQL and SQL Server.

## [0.1.1] - 2026-11-03

### Added

- **Text outside the `ermd-*` blocks is kept** — headings, notes and tables written in a `.ermd` file are no longer
  overwritten when the diagram is saved. The title is no longer replaced by the file name.
- **Readable Markdown** (off by default) — `markdown-er.markdown.generateMermaid` / `generateTableDocs` write a Mermaid
  `erDiagram` and a column table per table into the file on save.
- **File format versions and migration** — a diagram in an older format asks before it is updated (Update / Show changes /
  Not now / Don't ask for this file; `markdown-er.migration.prompt`), and **ER Diagram: Update File Format (Migrate)** /
  **… of All Files in Workspace** update files on demand. Files are never updated without asking.
- A file in a format newer than the extension opens **read-only** instead of being overwritten.

### Changed

- **File format v2: schema versions move to `<file>.ermd.versions.yaml`**, so snapshots no longer grow the `.ermd` file
  and its diffs. New files use v2; v1 files keep working as before until they are updated. Versions found in both files
  (e.g. added by an older extension) are merged.
- The seed data table scrolls on its own, with the header row and row numbers kept in view and the buttons below it.

## [0.1.0] - 2026-11-03

### Added

- **Column sets** — define common columns once (e.g. version, created at / by, updated at / by; **+ Audit columns** creates that set) and add them to tables from the table editor or to all tables at once. Changes to a set reach every table that uses it; sets can be added to new tables automatically. Stored in an `ermd-column-sets` block.
- **Type picker** — dictionary types and basic types as buttons grouped by category; pick a basic type, then enter its size; `varchar(50)`-style direct input; register a new dictionary type (with category) inline. Columns may now use a type without a dictionary entry.
- **Dictionary search** and category filter; a dictionary type's NOT NULL now applies to columns that pick it.
- **Oracle** dialect, alongside MySQL, PostgreSQL, SQL Server and SQLite.
- **CREATE DATABASE / USER / SCHEMA** with character set and collation per dialect (**Database** button); passwords are never stored.
- **DECIMAL precision and scale.**
- **DDL format options** — plain `CREATE TABLE` by default; comments, MySQL table options, explicit `NULL` and identifier quoting can be switched on in the DDL dialog or in Settings.
- **Save DDL… / Save data…** — write the DDL and the seed-data `INSERT`s to files; default file names in `markdown-er.ddl.outputFile` / `dataOutputFile`.
- **English / Japanese UI** (`markdown-er.language`, toolbar selector).
- **Extension icon.**
- **Toolbar split by role** — top bar for diagram-wide actions, vertical bar for canvas tools.

### Fixed

- Edits could be lost or written to the wrong file: saves are versioned and tagged with their file, pending saves are flushed before switching files, versions, DDL and closing; undo results are saved; loading a file clears the undo history.
- DDL correctness across dialects: column order (`DEFAULT` before `NULL`), auto-increment only for a single integer primary key that is not a foreign key, PostgreSQL identity columns and `setval` after seed inserts, SQL Server `IDENTITY_INSERT`, boolean defaults, foreign keys and seed data in dependency order, diff DDL with each dialect's `ALTER` syntax.
- The database schema and user were dropped when a file was reopened.
- Auto-layout menu closes on a canvas click or Escape; the toolbar no longer clips.

### Changed

- DDL generation is a class per dialect (`SqlDialect` subclasses) with unit tests.
- Supply-chain hardening: install scripts disabled, packages must be 7 days old, exact versions, CI with signature and audit checks, actions pinned to commit SHAs, Dependabot with a cooldown. Build tools upgraded (vite 6, vitest 4, vsce 4).

## [0.0.4] - 2026-05-22

### Added

- **CSV import — Tables** — Click **Import CSV** in the toolbar, select the **Table** tab, and upload a CSV file to import multiple tables and columns at once. Rows sharing the same `tablePhysicalName` are grouped into one table. Tables whose `tablePhysicalName` already exists in the diagram are skipped.
- **CSV import — Dictionary** — Select the **Dictionary** tab to bulk-import column-type dictionary entries from a CSV file. Entries with duplicate names are skipped.
- **Built-in type presets** — 14 named presets (ID, BigID, Name, Title, Email, Code, Text, Flag, Quantity, Amount, Timestamp, Date, JSON, NullableID) are available as `dictionaryName` values in the table CSV. Preset entries are auto-created in the dictionary on import.
- **`dictionaryName` column in table CSV** — Specify a dictionary entry or built-in preset by name instead of raw `dbType`/`length`/`notNull`. Resolution order: existing dictionary entry → built-in preset → raw type fields.
- **Free-form type input with autocomplete** — The type field in the column editor is now a text input with `<datalist>` suggestions from the dictionary. Typing an existing entry name selects it automatically.
- **Inline custom type registration** — When a typed type name is not in the dictionary, the input border turns amber and the **+** button turns orange. Clicking **+** opens an inline form (name pre-filled) to define dbType / length / notNull and register the new entry — all in a single undo-able action.

## [0.0.3] - 2026-05-22

### Added

- **Schema versioning** — Click **Save Version** in the toolbar to snapshot the current ER schema (tables, columns, relations, dictionary, layout) directly inside the `.ermd` file as an `ermd-versions` block. No git commit required.
- **Versions panel** — Click **Versions** in the toolbar to open a panel listing all saved versions (name, date, table count, relation count). Versions can be deleted with a two-step confirmation.
- **Version Diff DDL** — In the DDL modal, switch to **Version Diff** mode and select a From / To version (or "current state") to generate `ALTER TABLE` statements between any two snapshots. Powered by `DdlDiffer.diffModels()` which performs an in-memory structural diff with no git dependency.

## [0.0.2] - 2026-05-21

### Fixed

- Extension failed to activate ("command not found") because `js-yaml` was excluded from the `.vsix` by `.vscodeignore`. Switched to esbuild bundling so all runtime dependencies are inlined into `out/extension.js`.

## [0.0.1] - 2026-05-21

### Added

- Interactive ER diagram canvas backed by `.ermd` files (YAML front matter + `ermd-*` fenced blocks)
- Table CRUD — add, rename, delete tables with drag-to-reposition and resize handles
- Column CRUD inside the Table Edit Panel — logical/physical names, dictionary type, PK, nullable, default value
- Column-type dictionary — define reusable DB types (name / dbType / length / notNull) and apply them to columns
- Relation creation by dragging between tables; cardinality (1:1 / 1:N / N:N) and optional FK constraint
- Logical ↔ Physical name toggle — switch all labels with one click
- Persistent layout — table positions, viewport, and name mode saved back to the `.ermd` file automatically
- Full undo / redo via `Ctrl+Z` / `Ctrl+Y` (powered by zundo)
- Full DDL export (`CREATE TABLE` + `ALTER TABLE … ADD FOREIGN KEY`) via toolbar or Command Palette
- Diff DDL export (`ALTER TABLE` statements against a git baseline ref)
- Database dialect setting — MySQL, PostgreSQL, SQLite, SQL Server (`markdown-er.ddl.dialect`)
- Seed data editor — spreadsheet-like row editor per table (Definition / Seed Data tabs); saved in `ermd-table` block
- `INSERT INTO` export — optional seed data as SQL INSERT statements; option to skip auto-increment PK columns
- Auto Layout — arrange tables automatically (Vertical / Horizontal / Auto) via dagre; undo-able
- Region group boxes — labeled background rectangles; double-click to rename; undo-able; saved in `ermd-layout`
- Search box — filter tables and columns by name in real time
- Minimap toggle — show/hide the minimap overlay
- Fit View / Zoom In / Zoom Out buttons in toolbar
- Settings shortcut — ⚙ gear button opens VSCode Settings filtered to `markdown-er`
- Indexes and constraints — define indexes (UNIQUE / INDEX) and check/unique constraints per table; exported in DDL
- CSV import for seed data — import rows from a CSV file; download a column-header template CSV
